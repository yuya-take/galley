# Troubleshooting

実装が進んだら、実際に起きた問題と解決手順をここに追記する。

## 起動しない

```bash
# ローカル
cargo run -p galley-server

# Docker
docker logs <container>
docker ps -a
```

- `/data` に書き込めない → ボリュームの所有者とコンテナのユーザー（非 root）が合っているか確認する
- マイグレーションの失敗 → ログのマイグレーション名を確認する。リリース済みのマイグレーションを書き換えていないか

## ポート競合

アプリは :8080（画面・MCP）、資料配信は :8081 を使う。

```bash
lsof -i :8080
lsof -i :8081
```

## アクセスが拒否される（403）

- Host ヘッダーが `ALLOWED_HOSTS` にない → 環境変数にアクセスに使うホスト名を追加する
- `ALLOWED_HOSTS` が未設定 → localhost からのアクセスだけ受け付ける（起動ログに警告が出る）
- リバースプロキシ経由 → プロキシが元の Host を渡しているか、アプリと資料配信に別々のホスト名を割り当てているか
- POST が拒否される → Origin がアプリ自身か、独自ヘッダー付きの JSON で送っているか

## 資料が表示されない・崩れる

- iframe が空 → 資料配信のオリジン（:8081 / 資料用ホスト名）にブラウザから届くか確認する
- 画像・フォント・スクリプトが読み込まれない → CSP で外部リソースを止めている仕様。資料を「外部リソースを含まない単一 HTML」で作り直す
- ブラウザの開発者ツールのコンソールで CSP 違反のメッセージを確認する

## SQLite のロック（database is locked）

- WAL モードと `busy_timeout` が設定されているか
- トランザクション中にブロブの書き込みや外部 I/O をしていないか

## MCP に接続できない

- クライアントは社内ネットワークから直接つなぐもの（Claude Code など）に限る。クラウド側から接続する型のクライアントは社内のアプリに届かない
- `MCP_TOKEN` を設定している場合、`Authorization: Bearer` を付けているか
- `X-Author-Name` ヘッダーを設定しているか（未設定だと登録を拒否する）
- URL がアプリ本体の `/mcp`（:8080）になっているか
