# Rust Code Review

変更されたRustファイルに対して、静的解析ツールの実行とコードレビューを行う。

## 手順

### 1. 変更Rustファイルの特定

```bash
git diff --name-only HEAD -- '*.rs'
git diff --name-only --cached -- '*.rs'
```

変更がない場合はその旨を報告して終了する。

変更ファイルが属するcrateディレクトリを特定する（`Cargo.toml` の位置から判別）。

### 2. 静的解析の実行

対象crateのディレクトリで実行する:

```bash
# ビルド確認（これが通らなければレビュー中止）
cargo check

# lint（警告をエラーとして扱う）
cargo clippy -- -D warnings

# フォーマット確認
cargo fmt --check

# テスト
cargo test

# セキュリティ監査（利用可能な場合）
cargo audit 2>/dev/null || echo "cargo-audit未インストール"
```

いずれかが失敗した場合はエラー内容を報告し、修正案を提示する。

### 3. 手動コードレビュー

変更ファイルを Read で読み、以下の観点でチェックする。

---

#### CRITICAL（必ず修正）

**安全性**
- [ ] プロダクションコードに未チェックの `unwrap()` / `expect()` がない（`?` 演算子または `context()` を使用）
- [ ] `unsafe` ブロックに `// SAFETY:` コメントで不変条件が文書化されている
- [ ] 外部メッセージ（メッセージブローカー等）の `serde` デシリアライズが型安全に行われている
- [ ] メッセージペイロードのパース失敗時にパニックしない
- [ ] ハードコードされた認証情報がない
- [ ] `std::process::Command` にユーザー入力が直接渡されていない

#### HIGH（修正推奨）

**所有権・借用**
- [ ] 不要な `.clone()` がない（借用で済む場合）
- [ ] `String` パラメータで `&str` や `impl AsRef<str>` で済む箇所がない
- [ ] ライフタイム指定が適切

**非同期処理（Tokio）**
- [ ] asyncコンテキスト内でブロッキング操作がない（`std::thread::sleep`, `std::fs`）
- [ ] 共有型に適切な `Send` / `Sync` バウンドがある
- [ ] `tokio::spawn` のタスクが適切にエラーハンドリングされている

**エラー処理**
- [ ] エラー型が `thiserror` または `anyhow` で適切に定義されている
- [ ] ビジネスロジック上重要な `enum` に対してワイルドカード `_ =>` マッチがない
- [ ] メッセージブローカー等の接続エラーにリトライロジックがある

**コード品質**
- [ ] 関数が50行を超えていない
- [ ] `println!` / `dbg!` マクロが残っていない（`tracing` を使用）
- [ ] 不要な `pub` が付いていない（最小限の可視性）

#### MEDIUM（提案）

**パフォーマンス**
- [ ] ホットパスで不要なアロケーションがない
- [ ] サイズが既知の場合に `Vec::with_capacity` を使用
- [ ] ループ内での不要な文字列アロケーションがない

**イディオム**
- [ ] `clippy::allow` にコメントで理由が記載されている
- [ ] 公開APIに `///` ドキュメントがある
- [ ] イテレータチェーンの活用（手続き的ループの回避）

---

### 4. レポート生成

```
## Rust Review 結果

### 静的解析
- cargo check: ✓ / ✗
- cargo clippy: ✓ / ⚠️ {件数}件
- cargo fmt: ✓ / ⚠️ 要フォーマット
- cargo test: ✓ / ✗ {失敗件数}件
- cargo audit: ✓ / ⚠️ {件数}件 / 未インストール

### コードレビュー

#### CRITICAL
- `ファイルパス:行番号` — 問題の説明
  → 修正案

#### HIGH
- `ファイルパス:行番号` — 問題の説明
  → 修正案

#### MEDIUM
- `ファイルパス:行番号` — 問題の説明
  → 修正案

### 総合判定
- CRITICAL/HIGHがある場合: コミット前に修正を推奨
- MEDIUM以下のみ: コミットOK
```

## 注意事項

- 変更されたRustファイルのみをレビュー対象にする
- `cargo clippy` で自動修正可能なものは `cargo clippy --fix` を提案する
- `/code-review` との違い: このスキルはRust特化で静的解析ツールの実行と所有権・非同期の深いレビューを含む
